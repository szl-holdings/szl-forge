# Private archive handoff for Model Lab

This is a bounded local handoff for Model Lab's small CPU research tracks. It
stages **one** reviewed JSONL dataset from an owner-controlled local archive,
rehashes it before training, keeps the run in a separate local directory, and
can copy a completed small candidate back to that archive. No command here
contacts OneDrive, Hugging Face, GitHub, or either website. It does not train
general language models or change the fixed ReceiptAgent curriculum.

## Local path and request contract

Set the paths in the operator's shell, never in a committed file:

```powershell
$env:SZL_ARCHIVE_ROOT = '<private local archive root>'
$env:SZL_STAGE_ROOT = '<plain local work root outside the archive and checkout>'
```

Both roots must exist. Stage data, training output, and the private request must
stay outside the Git checkout; Model Lab requires a clean exact source commit.
The archive root must neither contain nor be inside the checkout. Placement checks run
before request or dataset reads and before candidate writes; using a local root
that is an ancestor of the checkout does not permit output inside the checkout.
The archive root may have a Windows Cloud Files reparse ancestor. Only recognized
cloud tags with a ready placeholder state are admitted. Symlinks, junctions,
unknown reparse tags, offline or recall attributes, and unstable reads are
rejected before copying. If the sync provider leaves a file in an unsupported
placeholder state, materialize it to a plain local input root outside the
archive and stage root first, compare it to the owner's expected SHA-256, then
pass `--materialized-input-root <that root>` to `stage-archive`. This fallback
does not establish a verified remote backup.

Windows checks use exact-entry native metadata because Python `lstat` and
handle-based attribute queries can mask cloud reparse tags. Plain-local work
rejects cloud ancestors. Drive/share anchors with a reparse attribute are denied
conservatively rather than inferred safe. Native lookup errors do not fall back
to Python's masked metadata, and no wildcard enumeration is used.

Keep the request JSON outside the repository. Its `archive_relative_path` is
relative to the selected input root. Its digests must come from separately
reviewed local evidence, not from a manifest generated by this tool:

```json
{
  "schema": "szl.model-lab.archive-request/v1",
  "track": "router",
  "archive_relative_path": "curated/reviewed-router.jsonl",
  "bytes": 1234,
  "sha256": "<64 lowercase hex characters>",
  "source_provenance_sha256": "<64 lowercase hex characters>",
  "rights_review_sha256": "<64 lowercase hex characters>",
  "leakage_review_sha256": "<64 lowercase hex characters>",
  "owner_release_sha256": "<64 lowercase hex characters>",
  "rights_status": "APPROVED_FOR_RESEARCH_TRAINING",
  "leakage_status": "PASS",
  "owner_release_status": "RELEASED_FOR_RESEARCH_TRAINING"
}
```

The four review digests and positive statuses are **operator assertions**. The
tool checks their shape and presence; it cannot independently verify the
underlying review, ownership, consent, or release. `Dataset.read` then checks
the Model Lab schema, size, provenance assertions, three splits, and exact
group/case leakage. Its format includes test rows in one file; control real
held-out access upstream. Do not put raw personal documents, scraped content,
secrets, or unreviewed records in this request.

## Stage, train, archive

After source and data review, a future authorized operator can run:

```powershell
szl-model-lab stage-archive --request '<private request file>' --output '<stage root>/run-001'
```

The command creates `data.jsonl` and `stage-manifest.json` only in a new local
directory. Record the returned `manifest_sha256` separately. The manifest
contains hashes and gate references, with no archive URL, local root, account,
or credential. Changing data or manifest after staging fails the training gate.

```powershell
szl-model-lab train --track router --data '<stage root>/run-001/data.jsonl' `
  --archive-stage-manifest '<stage root>/run-001/stage-manifest.json' `
  --archive-stage-sha256 '<recorded manifest SHA-256>' `
  --output '<stage root>/candidate-001' --source-revision '<clean 40-hex Git revision>' `
  --acknowledge-research-only
```

The CLI checks the stage and local output location before importing Torch. The
candidate output must be outside the input stage itself and all its descendants;
use a sibling directory as in the example. Both the CLI and direct training entry
reject overlap before reading the dataset, fitting, or writing the candidate.
The trainer rechecks stage bytes before fitting and after fitting, and binds the
stage and review digests into the candidate's dataset receipt. Its existing
source, split, and publication gates remain in force. The output is a new
local research candidate, not a promoted model or a restartable optimizer
checkpoint. Do not run this step until owner release and held-out access are
authorized for the actual dataset.

```powershell
szl-model-lab archive-candidate --candidate '<stage root>/candidate-001'
```

This last command accepts only the five-file Model Lab candidate format with
its exact small safetensors layout and a bound archive stage. It excludes
extra files, rejects suspicious text metadata, copies into a new archive
pending directory, rehashes the local copies and receipt, then renames the
complete directory to `candidate-<manifest hash prefix>`. A failed copy leaves
its `.pending-*` directory as incomplete evidence; a retry can create a new
pending directory without treating the failed one as a candidate. Review any
pending directory before manual cleanup. Only the final directory with its
receipt represents a locally verified copy.
The receipt records `LOCAL_COPY_VERIFIED_REMOTE_UNVERIFIED` and
`checkpoint_completeness: NOT_RESTARTABLE`. It is **not** a multi-GB model
backup, a resumable training checkpoint, or an independent remote-byte restore.
Keep local originals until an independent remote restore verifies exact bytes.

## Estate mapping

Forge keeps source, data admission, run receipts, and promotion decisions.
Hugging Face model or dataset publication would require its separate reviewed
writer, immutable artifact identity, rights, evaluation, and owner release
gates. The product surface at `a-11-oy.com` and the proof surface at
`a11oy.net` should show only those later measured states and receipts. A local
archive copy or reachable sync folder does not change either public claim.
