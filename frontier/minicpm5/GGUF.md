# MiniCPM5 official GGUF: P1 CPU evaluation, not model promotion

GitHub -> Hugging Face -> a-11-oy.com -> a11oy.net.
Forge owns evaluation and runtime qualification; Nemo witnesses inference
boundaries; Serve owns the existing studio's recipes/validators/receipts.
Do not replace the public studio, create another flagship or mirror weights.

## What is pinned

The canonical plan is generated by `inference/minicpm5_gguf.py` and checked into
`gguf-plan.v1.json`. It binds official upstream Q4_K_M, Q8_0 and F16 filenames,
full repository revision, file sizes and LFS SHA-256 identities, plus the exact
llama.cpp Linux x64 release archive and source commit. Source:
https://huggingface.co/openbmb/MiniCPM5-2B-GGUF

Only Q4_K_M is selected by default for an explicitly launched experiment. A
source check verifies all three metadata identities but downloads no weights.
The pinned repository revision includes card-only updates: those updates are
not a new material model release. Actual GGUF bytes, not card recency, motivate
this extension to the previously admitted edge lane.

The archive belongs to llama.cpp build b10809, whose release metadata marks it
prerelease. A fixed archive hash prevents a replaced tag asset being admitted,
but does not prove host-library or container-image closure. Both remain separate
qualification gates. Apache-2.0 is the model card's declared license, not a
substitute for constituent-source/attribution review.

## Commands from the Forge repository root

```bash
python -m unittest discover -s tests -p 'test_minicpm5_gguf.py' -v
python -m inference.minicpm5_gguf plan
python -m inference.minicpm5_gguf source --output artifacts/gguf-source.json
```

The default command and all PR checks are plan/offline/metadata only. Actual
execution requires an explicit command on a Linux x86-64 evaluation host:

```bash
python -m inference.minicpm5_gguf run --variant Q4_K_M \
  --source-revision "$(git rev-parse HEAD)" --output artifacts/gguf-run.json
```

Allow sufficient RAM for the selected file, context and runtime. No claim is
made that the advertised 131K context fits a device; this profile is capped at
4096 context and 96 generated tokens per case. Explicit Q8_0/F16 execution needs
its own resource budget; the ordinary plan does not run those variants.

The runner downloads one exact GGUF and one SHA-verified official CPU archive
into a new temporary directory. It starts only its own server on 127.0.0.1 with
an ephemeral API key and sanitized environment, does not use ambient credentials,
limits requests/bytes/time, and stops the process and deletes temporary files on
exit. No tools, data ingestion, training, Hub writes or public listener exist.
The output contains hashes, grades and timings, not raw model reasoning or text.
Exit 0 is SMOKE_PASS; 2 is completed SMOKE_FAIL; 1 is INCOMPLETE. Every outcome
remains HOLD. A failed attempt must be retained, not silently retried to green.

## Baseline and comparison discipline

The September 7 historical GPU run was **float16 execution**, not a measured
BF16 baseline. It passed 9/12 synthetic probes. Failed probes 00/04/10 remain
immutable historical negative evidence. The new evaluator imports the exact
original system prompt, suite and grader; it verifies their source digest and
the complete baseline record before execution. No grammar constraint or tool
execution is added to improve the pass rate.

CPU llama.cpp versus historical A10G Transformers is a **behavioral reference**,
not a controlled quantization experiment. Different engines, templates and
hardware confound direct attribution. A new result reports recovered/newly failed
case IDs and output-hash matches, never a quantization-parity or speedup claim.
The timing is loopback request roundtrip, not historical GPU generation-call
latency, TTFT or production throughput. VmHWM is this server's resident high-water
mark, not total host memory or a GPU allocation counter. Cost/energy stay unknown.

The GGUF conversion lineage to the exact historical base checkpoint is not
proven by upstream branding alone. Before promotion, compare F16 and quantized
variants in a matched runtime on the same hardware; bind tokenizer/template and
conversion provenance; evaluate independent held-out and longer-context tasks;
then exercise Nemo/Serve/controller isolation, abstention and fallback/rollback.
A source or small synthetic PASS cannot satisfy these gates.

## Codex and publishing handoff

Collect one bounded result per versioned experiment. Verify the final canonical
record digest before storing evidence. Keep the prior baseline unchanged and
record the executed source commit separately from any later evidence commit.
The result may be presented as measured research with limitations by the existing
HF artifact publisher. Product and proof owners must retain modelOperational=false
and productionDisposition=HOLD until their own admission and live-readback gates
pass. This source change does not deploy those surfaces or enable a schedule of
paid model runs.
