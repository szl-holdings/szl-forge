# Model source-binding report fields

`tools/publish_model_source_bindings.py` emits
`szl.model-source-binding-report/v2`. Its generated binding document and a
preserved immutable owner publication are different objects. In particular,
`VERIFY_IMMUTABLE_RELEASE` does not replace the owner's `publication.json` with
the generated `szl.hf-model-source-binding/v2` document.

Each result identifies the generated bytes explicitly:

- `generated_binding_sha256`: SHA256 of canonical generated binding JSON.
- `generated_binding_schema`: the generated document's schema.
- `publication_sha256`: retained compatibility alias for
  `generated_binding_sha256`, not a claim about the preserved owner's file.
- `publication_sha256_basis`: `GENERATED_CANONICAL_BINDING_JSON`.

Publication effects are separate from that digest:

| Result path | Generated upload | Generated exact-byte readback | Generated Hub revision | Preserved publication |
| --- | --- | --- | --- | --- |
| Preparation / dry run | false | false, not performed | null | null, no preservation claim inferred |
| Immutable verification | false | false, not performed | null | Unchanged by this invocation at the pinned revision; byte hash UNKNOWN to this producer |
| Generated publication completed | true | true | Exact upload/readback revision | null, not the immutable-preservation path |

These columns map to `generated_binding_uploaded`,
`generated_binding_exact_byte_readback_verified`,
`generated_binding_hub_revision`, and `preserved_publication`.
For immutable verification, the last field has an explicit null `sha256` and
`sha256_status: UNKNOWN_NOT_READ_BY_THIS_PRODUCER`. No extra existing-publication
download is added. False generated-readback status means no check was performed
on those generated bytes; it does not say that the preserved file is corrupt.

The upload flag is set to null immediately before calling the provider, then
true only after the upload call returns. If that call raises, the remote effect
can be UNKNOWN. The readback flag stays false until exact bytes match. Thus a
readback failure after a successful upload leaves upload true and verification
false in the in-memory result; no successful aggregate report is emitted.
An absent or failed aggregate report never proves zero preceding remote effects.

An independently fetched preserved-file hash belongs in its own exact-revision
readback record. Do not overwrite the owner's file or reinterpret historical
reports to make the two hashes agree. Preservation is scoped to this invocation,
not a guarantee that no other writer ever changed repository main.

These fields grant no runtime, training, signing, publication or autonomy
authority. Metadata byte verification does not establish weight application,
model quality, held-out evaluation, independent certification, or a qualified
compute/budget window. Existing eligibility and failed evaluation gates remain
unchanged.
